Développement

Environnement local, outils de qualité, vérifications automatiques et pièges connus de SPIP.

Environnement local (ddev)

ddev start     # démarre web, db, phpmyadmin
ddev launch    # ouvre https://ccn.ddev.site

Chaque instance a son nom d’hôte, déclaré dans .ddev/config.yaml :

InstanceURL
Fictionshttps://ccn-fictions.ddev.site
On tourne (thematique)https://ccn-ontourne.ddev.site
Petit fablabhttps://ccn-petitfablab.ddev.site
Digitalycéen (Edifice)https://edifice-digitalyceen.ddev.site

Après une modification de squelette, si le comportement semble périmé, videz le cache SPIP du site concerné :

rm -rf sites/<site>.ddev.site/tmp/cache/*

Qualité de code

À lancer depuis le dossier d’un plugin, par exemple plugins/projets/thematique/ :

composer check-cs          # Easy Coding Standard : vérifie le style
composer fix-cs            # corrige le style automatiquement
composer rector-dry-run    # simule les migrations Rector
composer rector            # applique les migrations Rector
vendor/bin/phpstan analyse # analyse statique (niveau dans phpstan.neon.dist)

Lints CI

Le workflow .github/workflows/lint.yml s’exécute avant chaque build Docker (dev et main) et bloque la publication de l’image en cas d’échec. Ils couvrent les plugins thematique, fictions, petitfablab et ccn, ainsi que cette documentation.

Les scripts Node nécessitent npm ci au préalable. Pour accepter une exception légitime, relancez le script avec --write-baseline, puis vérifiez que le diff de la baseline ne contient que le cas attendu. Le détail des règles et des exceptions est dans .ci/README.md.

Tests

Il n’y a pas de suite de tests automatisés. La vérification repose sur les lints ci-dessus et sur un test manuel sur une instance ddev réelle : plusieurs erreurs de squelette compilent sans erreur mais cassent le rendu (voir ci-dessous).

Pièges SPIP

#SET{var, [(...)]} casse la sortie

[( )] est la syntaxe du bloc conditionnel, pas un simple emballage de valeur. Utilisé comme valeur d’un #SET, il n’affecte rien : le résultat est recraché dans la page avec une accolade en trop, sans erreur PHP, ce qui peut corrompre du JSON ou du HTML.

# Faux : casse la sortie
#SET{id_rubrique, [(#VAL{ressources}|thematique_id_rubrique_a_mot)]}

# Correct : #SET sans crochets
#SET{id_rubrique, #VAL{ressources}|thematique_id_rubrique_a_mot}

Les crochets ne servent que pour un test ou un texte conditionnel : [(#GET{x}|=={y}|oui) texte].

Item de langue comme argument de balise

<:module:cle:> n’est accepté ni comme argument d’un #FORMULAIRE_XXX{...}, ni comme valeur d’un #SET{...} : le texte traduit s’affiche suivi d’une accolade orpheline, et l’argument n’est jamais transmis.

# Faux : « Libellé} » s’affiche, le formulaire ne reçoit rien
#SET{label, <:thematique:label_xxx:>}

# Correct : traduire avec le filtre _T, puis passer par #GET
#SET{label, #VAL{thematique:label_xxx}|_T}
#FORMULAIRE_CCN_JOINDRE_DOCUMENT{#ID_ARTICLE,article,#GET{ext},#GET{label}}

#CONST{...} et #GET{...} passent sans problème comme arguments.

Dans les deux cas, le squelette compile sans erreur. Testez toujours le rendu réel de la page ou de l’endpoint concerné (par exemple ?page=json&mode=projet), pas seulement la compilation.

Commentaires (#REM)

Le texte d’un [(#REM) ...] est compilé comme du squelette : un ] le ferme trop tôt, une balise mal formée casse tout le squelette. Citez les balises sans # (CACHE{0}), les boucles sans < (BOUCLE_x), les items de langue sans <: :>. Le code désactivé se supprime : il reste dans l’historique git.

Conventions de commit

Format type(scope): message, en français. Le scope est le nom du plugin concerné.

feat(thematique): limitation des images à 380x380
fix(thematique): fermeture automatique du menu d'édition
perf(thematique): images jointes réduites à 760 px
refactor(ccn): ratio de la vidéo calculé une seule fois

Types utilisés : feat, fix, perf, refactor, chore. Une modification de code qui change un comportement décrit ici met à jour la page concernée dans le même commit. Le développement se fait sur dev, puis une pull request dev → main déclenche la publication (voir Déploiement).
