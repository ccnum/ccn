Déploiement

Le projet est distribué sous forme d’image Docker erasme/spip-ccn, configurée par variables d’environnement.

Docker

cp .env.example .env   # remplacer toutes les valeurs
docker-compose up

docker-compose.yml lance une base MariaDB et le conteneur SPIP, avec des volumes pour les données de la base, IMG/, la configuration et les logs.

Ne commitez jamais un .env contenant de vrais identifiants. En production, les variables passent par docker-compose.yml ou le gestionnaire de secrets du cluster.

Variables d’environnement

VariableDescription
SPIP_AUTO_INSTALLInstalle SPIP automatiquement s’il ne l’est pas.
SPIP_DB_SERVERType de serveur de base de données utilisé par SPIP.
SPIP_DB_LOGIN, SPIP_DB_PASS, SPIP_DB_NAMEIdentifiants et nom de la base.
SPIP_SITE_ADDRESSURL du site.
SPIP_ADMIN_EMAIL, SPIP_ADMIN_PASSCompte administrateur créé à l’installation.
SPIP_VERSION_SITEthematique par défaut ; une valeur contenant fictions active le plugin fictions, idem pour petitfablab.
SPIP_PLUGINS_CIOIDCtrue pour activer la connexion SSO laclasse.com.
SPIP_CIOIDC_CLIENT_NOM, SPIP_CIOIDC_CLIENT_SECRETClient OpenID Connect enregistré sur le serveur laclasse.com (requis si le SSO est activé).
SPIP_PLUGINS_IMPORTS_UTILISATEURStrue pour activer la page d’import de comptes par CSV (voir Import de comptes). Désactivée par défaut.
PROJETlaclasse par défaut, ou edifice.
APACHE_PORTPort d’écoute d’Apache dans le conteneur.
VIMEO_ACCESS_TOKENJeton d’accès à l’API Vimeo.
SPIP_FACTEUR_SMTP_HOST, SPIP_FACTEUR_SMTP_PORT, SPIP_FACTEUR_SMTP_SECUREServeur SMTP d’envoi des e-mails (plugin facteur) ; SPIP_FACTEUR_SMTP_HOST bascule l’envoi en SMTP, SPIP_FACTEUR_SMTP_SECURE vaut non, tls ou ssl.
SPIP_FACTEUR_SMTP_USERNAME, SPIP_FACTEUR_SMTP_PASSWORDIdentifiants SMTP ; un identifiant renseigné active l’authentification. Le mot de passe passe par le gestionnaire de secrets en production.
SPIP_FACTEUR_FROM_EMAIL, SPIP_FACTEUR_FROM_NOMAdresse et nom de l’expéditeur des e-mails.
SPIP_TEST_EMAIL_DESTPériode de test : tous les e-mails partent vers cette adresse (ou ces adresses, séparées par des virgules) au lieu de leurs destinataires, copies comprises. Écrite dans config/mes_options.php comme constante _TEST_EMAIL_DEST du plugin facteur, seulement si elle est renseignée : vide, les envois sont normaux. À vider avant l’ouverture aux classes.
CCN_PROJET_ACTIVEfalse pour un projet archivé, qui ne repart pas d’une année sur l’autre : plus de création automatique de la structure de rentrée, et seuls les webmestres peuvent se connecter via l’ENT.

config/_config_cioidc.php est régénéré à chaque démarrage du conteneur à partir des variables SPIP_CIOIDC_* : une modification prend effet au redémarrage suivant.

Les variables SPIP_FACTEUR_* sont réécrites dans la configuration de facteur à chaque démarrage et priment sur la saisie dans /ecrire. Une variable absente ou vide ne touche pas au réglage correspondant : un site sans ces variables garde la configuration SMTP saisie à la main.

Images publiées

DéclencheurImage
Push sur deverasme/spip-ccn:dev
PR fusionnée dans mainerasme/spip-ccn:latest et erasme/spip-ccn:X.Y.Z
Nouvelle version de PHP dans l’image de base (vérifié chaque nuit, vers 3 h ou 4 h à Paris)Reconstruction de dev et latest la nuit suivant la sortie : le redéploiement de latest redémarre les sites, il n’est fait qu’entre 18 h et 8 h (heure de Paris).

Chaque build est précédé des lints CI : un lint en échec bloque la publication. Un pod ne prend la nouvelle image qu’à son redémarrage (imagePullPolicy: Always).

Gestion des versions

Les versions suivent le format X.Y.Z. À chaque pull request fusionnée dans main, un tag est créé sur GitHub et l’image correspondante est publiée sur Docker Hub.

Pull requestExempleIncrément
Sans labelMaj de code / rajout de fonctionpatch : 1.0.0 → 1.0.1
Label #minor#minor - MAJ de version Y de SPIPmineure : 1.0.0 → 1.1.0
Label #major#major - MAJ de version X de SPIPmajeure : 1.0.0 → 2.0.0

Helm (Kubernetes)

Le chart du dossier helm/ déploie une instance (MariaDB, SPIP et un volume persistant). Une release par site, avec un fichier de valeurs dédié :

helm install fictions ./helm --namespace ccn -f custom.yaml
helm upgrade fictions ./helm --namespace ccn -f custom.yaml
helm uninstall fictions --namespace ccn

Les variables d’environnement ci-dessus se passent dans spip.env du fichier de valeurs.

Nouvelle CCN : pensez à configurer le SMTP dans l’espace privé du site.
